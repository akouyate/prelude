# Organization profile & billing hardening: declared country, per-recipient language, currency integrity

**History.** Drafted 2026-08-17, then adversarially challenged (HR-SaaS product expert, most capable model). The challenge overturned the draft's two central mechanisms and the user ratified the reversals: rule 2 (org language) DROPPED for per-recipient locale, rule 3 (onboarding ask) DROPPED for settings-only declaration, rule 5 (Stripe Customer seeding) DROPPED, and three money protections added while production has zero paid lots. User decisions 2026-08-17: settings-only ✓ (after the currency question was answered: display currency comes from request geography, never from the profile), per-recipient language ✓, all three money extras included ✓.

## Binding product rules

1. **`Organization.country`** (ISO-3166-1 alpha-2, nullable) is a **declared jurisdiction hint** — never a fiscal fact and **never a currency input**. Fiscal authority stays the address Stripe collects at checkout (`billing_address_collection: "required"`). Reserved future consumer: compliance/jurisdiction routing (candidate-consent regime, AI-hiring-law obligations — own ticket). This phase the field has exactly ONE reader: the settings form that writes it. Any PR adding a second reader must name this wall in a comment and justify non-fiscality. Analytics may read it only alongside `CreditLot.billingCountry` and must label it "declared".
2. **No `Organization.preferredLanguage` — ever.** `User.preferredLanguage` exists with a full chain (settings-language-select → user-actions → user-locale → i18n-provider). Notifications are per-recipient fan-outs; the language driver is the RECIPIENT's `User.preferredLanguage`, threaded through the notification service, with `NotificationDelivery.locale` recorded for audit. Template translation stays with the notifications-i18n ticket — this phase delivers the locale TO the template.
3. **No onboarding change of any kind.** `organizationOnboardingStepSchema` and `organizationOnboardingStateSchema` untouched. `Organization.country` is settings-only: written exclusively by a deliberate owner/admin submit of the existing `updateWorkspaceProfile` action. `null` means "nobody told us". No inference, no pre-guess, no backfill, no write from any other code path. The select defaults to "Not set"; the browser locale may visually SUGGEST, never submit.
4. **Display currency chain**: explicit user toggle > **server-resolved request geography** > EUR. It NEVER reads `Organization.country`. Resolved in the billing loader via `x-vercel-ip-country` when present, else the request `Accept-Language` region; passed as initial state; the client `navigator` effect (settings-billing-section.tsx:187-190) is DELETED, not kept as fallback. `defaultDisplayCurrency` gains a country-code overload (US → USD, else EUR — map unchanged, incl. for CA/UK/CH: they see EUR, consistent with what Checkout quotes them). **Display integrity**: the toggle must reflect the currency `creditPackAmountCents` actually returned — a pack with `unitAmountCentsUsd === null` prints EUR and the toggle says EUR; pinned by test.
5. **`ensureStripeCustomer` is not modified.** No address seeding — the Customer's address has exactly one author: the buyer at Checkout (`customer_update.address: "auto"`). Comment on the function saying why (an unverified declared country must never sit on a fiscal object that may never see a payment).
6. **Settlement currency lock**: `CreditWallet.settlementCurrency String?`, set by `grantPurchasedCreditLot` from `session.currency` on the FIRST paid lot; any later purchase in a different currency is REFUSED (no credits granted, `needs_admin`-grade park with reason `currency_mismatch` — an operator decides, never an automatic conversion). Rationale: the prorata auto-refund computes `unconsumed × unitAmountCents`; mixed-currency lots make that ambiguous on the one path that must stay computable. Free lots (First Five) never set nor check it.
7. **Observed billing country**: `CreditLot.billingCountry String?` written at fulfilment from `session.customer_details.address.country` — the tax-grade fact, captured where `session.currency` is already read. NEVER copied to `Organization.country`; observed and declared stay separate columns with separate authority.
8. **Checkout locale**: `locale` passed to `stripe.checkout.sessions.create` from the acting user's `coerceConsoleLocale(User.preferredLanguage)` — a French buyer gets a French payment page.

## What NOT to build (challenge-ratified)

No `Organization.preferredLanguage`. No onboarding change. No inferred write to `Organization.country` (not navigator, not geo header, not Stripe address, not backfill). No `address` on `ensureStripeCustomer`. No `Organization.country` read in any billing/tax path (grep-level review rule). No third currency in `currency_options`, no FX conversion. No template translation. No country display outside settings.
